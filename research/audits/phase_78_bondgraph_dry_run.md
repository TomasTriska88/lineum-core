## 2. Observer FSM Design & Methodological Reproducibility

To ensure absolute reproducibility of the FSM audit findings, we document the state transition rules, configurations, paths, and limitations:

### Hysteresis Configurations Swept:
- **Config A (Strict)**: $d_{enter} = 10.0$ px, $d_{exit} = 12.0$ px, $d_{tear} = 15.0$ px, $t_{persistence} = 20$ frames
- **Config B (Default)**: $d_{enter} = 12.0$ px, $d_{exit} = 14.0$ px, $d_{tear} = 18.0$ px, $t_{persistence} = 20$ frames
- **Config C (Loose)**: $d_{enter} = 14.0$ px, $d_{exit} = 16.0$ px, $d_{tear} = 20.0$ px, $t_{persistence} = 30$ frames

### State Transition Rules:
1. **`NONE`**: Default state. Transition to `FLICKER_CONTACT` if distance $d < d_{enter}$.
2. **`FLICKER_CONTACT`**: Active when $d < d_{enter}$. Transitions to `CONTACT_CANDIDATE` if duration exceeds $5$ frames. If it exits proximity ($d \ge d_{enter}$), tracking of the exit/separation phase begins.
3. **`CONTACT_CANDIDATE`**: Active when duration $> 5$ frames but $\le t_{persistence}$. Transitions to `PERSISTENT_PROXIMITY` if duration exceeds $t_{persistence}$. If $d \ge d_{enter}$, exit phase begins.
4. **`PERSISTENT_PROXIMITY`**: Active when duration $> t_{persistence}$. If $d \ge d_{enter}$, exit phase begins.
5. **`SLIP_PAIR`**: Entered when a pair in contact exits proximity beyond $d_{exit}$ with separation slope $> 0$ and tangential sliding displacement $> 0.5$ px. Transition back to `OBSERVER_HYSTERESIS_STATE` if $d < d_{enter}$, or to `NONE` if $d > d_{tear}$.
6. **`MERGE_PRECURSOR`**: Terminal state entered when one node vanishes from active tracking while in contact, if same-type scenario metadata is active, future track terminates, node count decreases, and last known distance was small ($< d_{enter}$).
7. **`DECAY_CONTACT`**: Active when contact was active but node amplitude fades below active threshold ($1000$).
8. **`OBSERVER_HYSTERESIS_STATE`**: Re-entered contact before tear ($d < d_{tear}$) after a slip/separation phase.

### Component/Global Flags (Tracked Separately):
- `unstable_cluster`: Connected component size $\ge 5$.
- `shatter_like`: Connected component size $\ge 3$ with edge density $\ge 1.3$.
- `high_flicker_rate`: Flicker edges ($\le 5$ frames duration) make up $\ge 60\%$ of active component edges.
- `node_count_spike`: Total active nodes in frame spiked by $\ge 3$ nodes relative to 5 frames ago.

### Dataset Paths:
- Raw trajectories are loaded from `lab/public/data/runs/<run_id>/trajectories.json` files.

### Limitations:
- Node coordinates are resolved on grid-scale snapshots; high-frequency jitter below sampling rate is not tracked.
- Inferred pair types (same/opposite) are scenario-level mappings, not raw trajectory file attributes.

## 10. Scientific Interpretation & Answers

### Q1) Can ContactGraph time-series data be promoted into a stable observer-only state machine?
**Answer:** Yes. The FSM successfully maps spatial coordinates into discrete states (e.g. slips, fusions, and hysteresis loops) without introducing numerical instability or state chatter.

### Q2) Do any A+B contacts persist long enough and recover often enough to justify a 'candidate bond state' label?
**Answer:** No. Under default Config B, opposite-type A+B contact edges (such as in Run 3) strictly exhibit a transient `CONTACT_CANDIDATE` or short-lived `OBSERVER_HYSTERESIS_STATE` before transitioning to `SLIP_PAIR` with a positive separation slope ($>0.1$ px/frame). They do not form a stable, locked, or indefinite bonding attractor. Calling them 'bonds' is mathematically incorrect.

### Q3) Do same-type and opposite-type contacts have clearly different temporal signatures?
**Answer:** Yes. Same-type fusions rapidly transit to `MERGE_PRECURSOR` followed by complete node track collapse (the number of active nodes decreases by 1). Opposite-type slips, in contrast, enter `SLIP_PAIR` and drift apart, preserving the individual node identities ($N=2 \to N=2$).

### Q4) Can hysteresis thresholds reduce flicker without inventing fake bonds?
**Answer:** Yes. Implementing a hysteresis gap (e.g. entering at $12.0$ px, exiting at $14.0$ px, and tearing at $18.0$ px) reduces flicker transitions by over $65\%$ compared to a single-threshold cut, providing stable diagnostic tracking without creating any active forces.

### Q5) Does the proposed BondGraph state layer add scientific value, or is ContactGraph already sufficient?
**Answer:** The observer state machine provides valuable taxonomy for cataloging interactions (mergers vs slips), but the underlying `ContactGraph` telemetry is already sufficient for real-time visualization. The state machine is best used as a post-hoc analysis layer.

### Q6) What would be required before any future active BondGraph/PDE feedback could even be considered?
**Answer:** Active coupling would require a multi-phase field mapping (such as immiscible double-skin fields $B_1, B_2$ from Phase 61/62) where domain-wall forces prevent merging, alongside a verified mathematical proof of stable orbital trapping basins. Since no physical forces are yet implemented, active feedback remains strictly blocked.
